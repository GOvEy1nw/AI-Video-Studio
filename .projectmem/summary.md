# projectmem - AI-Video-Studio

_Last updated: 2026-08-17_

## Project purpose
AiVS is a local-first Electron desktop application for project-based AI image, video, music, and sound-effect creation. It gives Windows/NVIDIA users curated Quick Gen, Director, Video Editor, and Asset Library workflows backed exclusively by the bundled local WanGP/Wan2GP runtime.

## Decisions
- AiVS generation is local-only and all normal image, video, music, and SFX inference routes through WanGP/Wan2GP; no hosted fallback or second runtime [backend/services/wangp_bridge.py]
- Product-visible models and capabilities are curated in backend/model_profiles/profiles.py and consumed by the renderer through the profile API [backend/model_profiles/profiles.py]
- Renderer HTTP uses frontend/lib/backend.ts with the Electron-provided loopback URL and session token; native capabilities cross only the typed shared/electron-api.ts preload boundary [shared/electron-api.ts]
- ProjectContext owns project assets, timelines, Director documents, navigation, and queued persistence; Quick Gen orchestration stays in useGenSpaceController [frontend/contexts/ProjectContext.tsx]
- useGenerationJob is the single shared owner for active generation requests, progress polling, cancellation, terminal guards, cleanup, and immutable submission snapshots [frontend/hooks/generation/useGenerationJob.ts]
- Visited Quick Gen, Director, and Video Editor workspaces stay mounted to preserve authored state; inactive workspaces must suppress playback, shortcuts, polling, and expensive media work [frontend/views/Project.tsx]
- Electron owns project/file storage, approved paths, ffmpeg export, runtime setup, and backend supervision; the renderer remains context-isolated with Node integration disabled [electron/main.ts]
- Audio Speech supports up to two ordered, trimmed voice references and switches to speaker-assigned segments for dialogue; WanGP mapping is model-aware (OmniVoice AB, Index TTS 2 AB2) while zero/one-reference speech remains a normal prompt. [frontend/views/genspace/audio/]
- MiniMax H3 is exposed as one curated experimental video profile; backend media-role routing selects FL2VA or Ref2VA, prompt media uses stable aliases, and the combined automatic model pack is enabled after the user's explicit distribution-scope confirmation while retaining visible license metadata. [backend/model_profiles/profiles.py]
- AIVS-003 keeps MiniMax H3 inside the existing video profile/handler/bridge path: backend routes selected input roles to FL2VA or Ref2VA, compiles persisted @ aliases to WanGP <Picture N>/<Video N>/<Audio N> labels, and the pack runner resolves both model types as one deduplicated pack.
- H3 media mutual exclusion is enforced at its existing H3MediaInputs add, drop, file-picker, and one-shot prompt-picker boundary; conflicting restored inputs remain removable. [frontend/views/genspace/video/VideoMediaInputs.tsx]
- H3 reference availability is a shared pure calculation for FL2VA exclusion, 9/2/2 per-kind and 12-total caps, and audio-to-visual balance; both picker and mention menu consume it. [frontend/views/genspace/logic/media-inputs.ts]
- WanGP source uses branch promotion instead of immutable pins: local AiVS development references an external Wan2GP checkout on the dev branch, while installed AiVS first-run/update setup pulls the latest Wan2GP AiVS branch through bundled MiniGit. [scripts/wangp-source.json, electron/python-setup.ts]
- AIVS-005 resolves development WanGP only from WANGP_ROOT then WANGP_WGP_PATH with wgp.py/shared/api.py/requirements.txt validation; installed Windows uses an app-managed transactional clone rooted under userData/runtime/Wan2GP, while models stay under userData/models. [electron/python-setup.ts]
- AIVS-005 is Windows-only: external Wan2GP development and app-managed first-run source bootstrap apply to Windows; existing macOS/Linux scripts are left unchanged and unsupported-platform cleanup is out of scope. [scripts/setup-dev.ps1, scripts/local-build.ps1]
- No retained AiVS script may clone, fetch, switch, or recreate a repo-local Wan2GP checkout; unsupported macOS/Linux helpers may validate an explicit external root only, while packaged source management remains Windows-only. [scripts/ensure-wan2gp.ps1, scripts/ensure-wan2gp.sh]
- AiVS root wgp_config.json is a read-only seed template; runtime initializes and updates an app-owned config copy so neither the AiVS checkout nor external Wan2GP checkout is modified. [wgp_config.json, backend/services/wangp_bridge.py]
- Wan2GP is externalized from AiVS: dev requires a read-only explicit external root; packaged Windows first-run/repair transactionally clones the moving AiVS branch into userData/runtime/Wan2GP with bundled MiniGit, while models and writable config remain app-owned. [scripts/ensure-wan2gp.ps1, electron/python-setup.ts]

Depth compiles to WanGP DV and excludes any other video from submission while retaining its disabled card.
